# Baseline and shared UI

Account Management 1.18.1 uses published delivery toolkit **1.5.3**, SPFx **1.23.2**, Heft **1.2.19**, TypeScript **~5.8.0**, React **17.0.1**, and Node **22.23.3**. Both channels retain the original PROD identities and product names. See [package identity and filenames](PACKAGE-IDENTITY.md).

Version 1.18.1 trims the delivered UI Kit assets without changing the pinned component packages. `scripts/subset-kit-styles.cjs` discovers live named Kit imports, bundles their reachable code for class and slot discovery, and retains the CSS for every state of those components. The checked-in subset replaces full Luma, theme and pattern styles. It also removes the adapter's duplicate full Luma asset. Run `npm run styles:compile` after changing Kit consumers; `npm run check` rejects a stale subset. Review font requirements when adding typography: current delivery retains normal Inter for international names and Latin italic for the static setup guidance. Unused Geist Mono and non-Latin italic files are omitted. Retained font subsets are separate webpack assets fetched only when matching text needs them.

The production adapter registers the subset inline and installs it once per owner document before host creation. Its global class names and Kit scope survive packaging; application CSS modules remain isolated. Font URLs use SPFx's webpack asset base in both embedded DEV and CDN PROD delivery. This avoids an external stylesheet load or nested relative font URL. `scripts/kit-css.test.cjs` exercises the production rules, both asset bases, CSP nonce, repeated instances, separate documents, stale CSS rejection and absence of full Kit assets. The manifests in `src/ui/kit.styles.json` and each release's `account-ui.styles.json` record inputs, selected bytes and retained fonts.

## Validation and future upgrades

Use Node 22.23.3, `npm ci`, and `npm run check`. For UI changes, run `npm run preview:build` and `npm run test:browser`; the browser harness uses fictional records and simulates assignment writes in memory. It makes no tenant writes. Install Playwright's Chromium once with `npx playwright install chromium` when needed. Commit source before running `package:dev` or `package:prod` for the requested channel. Finished builds are in `releases/<channel>/latest/`.

For another upgrade, review released contracts and migration notes, back up dirty or untracked work, create an app branch, and vendor exact archives and hashes. Refresh the lock deliberately. Preserve PROD IDs, Graph scopes, list and property names, configured flows and earlier releases. Do not use `npm audit fix` as an implicit upgrade.

Local tests do not prove tenant acceptance. Validate focus, dialog cancellation, live themes, remount, adjacent web parts, inline assignment saves and existing Power Automate writes in authenticated SharePoint. See [known issues](KNOWN-ISSUES.md).
